## 能否证明解释比规则更有用

20/20 份评审合同有效。目标覆盖原规则 54/60、强化规则 59/60、AI 60/60；清晰度分别为 3.65、4.70、4.85，谨慎度为 4.35、4.95、4.95。60 是十例乘三个目标乘两次展示，重复展示并非独立样本。固定评审本身存在位置敏感、相关错误和跨轮评分漂移，不能把这些主观分数叫作准确率，或根据单向偏好宣称胜出。

程序核验引用身份、状态和时序，不核验每句自由叙述的语义。模型评审未标记错误，但作者助手复核全部二十条归因时，仍认为首例的 `indicating a recorded acknowledgement or commit gap` 可能把机制写得过于确定；已成立的是回执记录早于 UNKNOWN，物理原因仍需证据。相邻的不确定性句子有帮助，不能取代语义核实。[助手定性复核](examples/ai-explanations/cross-event-luna-v4-round/assistant-text-audit.json)不是人工盲评、独立裁判或错误率估计，也没有产生额外请求。

当前可支持的结论是：**合同可靠性与显式关系覆盖提高；相对强化规则的实际解释价值仍待独立验证。** 不调整默认入口，不让 AI 获得任何执行或额度权限。

## 已交付的本地人工盲评工具

新增匿名候选页面、标注导入／导出和严格评分器。每例保留同一份记录证据、参考目标、三套实际展示及引用，隐藏来源名、模型、耗时、回退模式和评审分数；候选与案例顺序按种子随机。来源映射仅存于独立 `organizer/` 文件夹，提供给评审者的 `reviewer/` 不含映射。匿名是流程隔离，不是加密，措辞仍可能让人猜到来源。

页面只保留内存中的评分，导出 JSON 后可恢复，无自动上传或 API／交易调用；每次打开都是空白评分。允许平局，记录目标覆盖、清晰度、谨慎度、证据不足的断言、引用错误与越权建议。内容按纯文本渲染，离线页面的内容安全策略禁用网络连接。

评分器校验批次和内容哈希、全部案例位置、来源一一映射、合法分数与目标、重复 JSON 键和评审代号，拒绝陌生／重复案例。未完成案例保留在分母，不能变成胜出或平局；多人评分按原始案例汇总，分歧单列，不把重复评审膨胀成独立案例。导入文件是自报标注，不能据此验证身份或独立性。

**本轮实际人工评分为 0，`human_review` 仍为 null。** 页面验证只使用明确标注的合成测试值，没有填写或伪造人工研究结果。没有替用户联系任何人。

```sh
# 全部离线；新目录不覆盖已有盲评材料。
python3 scripts/build-human-review.py \
  --results docs/examples/ai-explanations/cross-event-luna-v4-round/results.json \
  --output target/human-review-v4

# 仅把 reviewer/ 交给未看过来源映射的人；直接打开其中的 review.html。
# 人员填写并导出后，在本地汇总：
python3 scripts/score-human-review.py \
  --packet target/human-review-v4/reviewer/packet.json \
  --mapping target/human-review-v4/organizer/source-mapping.json \
  --annotations path/to/export.json \
  --output target/human-review-summary.json
```

另附新实测数据的三版本对照 demo，可选择案例并查看引用。无需再次调用模型或连接数据库。

## 回归与边界

本地 34 个 Java 定向测试和 13 个 Python 测试通过。四轮共 40 条保留生成响应、8 个弃答对照离线回放，原合同的接受／拒绝、事实、检查项、归因、精确引用和文字均保持一致；没有额外付费。盲评页在浏览器验证了候选渲染、跨案例输入保留、评分导出／恢复和未完成标注不计分。[验证记录](examples/ai-explanations/cross-event-luna-v4-round/validation.json)区分本地检查与远端完整 CI。

交易／额度写入代码本轮未改变。既有真实 Mongo 非变更测试及五场景打包 HTTP 演示由完整 CI 再验证。API key 保留在私有忽略文件，模型覆盖只用于本次运行；不改动用户保存的默认模型配置。本项目仍是本地模拟器，全部案例为开发可见合成数据，尚无未见案例、人类独立评审或生产泛化证明。
