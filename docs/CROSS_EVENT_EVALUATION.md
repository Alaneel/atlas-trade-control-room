# Atlas 复杂异常解释：实现与真实对照结果

历史记录：本文保留最初两轮测量。后续同案例 GPT-5.6 Luna 比较及 80% 回退诊断见 [Luna follow-up](LUNA_EVALUATION.md)。

结论：已加入跨事件归因、精确证据引用和只读 API，但本次测试没有证明当前 AI 配置有稳定优势。强化规则版更完整、更快，因此界面默认选择强化规则，AI 保留为实验选项。

模型固定为 `gpt-4.1-mini-2025-04-14`。十二个合成案例在第一次调用前冻结：十个可解释案例和两个应当弃答的证据控制。生成模型看不到参考目标。所有规则、提示词、原始模型输出、失败、评审输入、隐藏来源映射和源文件哈希均保留。

## 实现内容

跨事件解释覆盖回执早于或晚于首次 UNKNOWN、重复 UNKNOWN、后续成功或拒绝结算、提交前延迟、回执与状态之间的记录间隔、时间戳倒序和缺失回执。每条解释分开显示：

1. 程序核对过的记录关系，包含状态与时间间隔。
2. 对这一关系的可能解释。
3. 尚不能确定的事情，以及具体事件/回执引用。

模型文字不是已验证根因。程序检查引用身份、时序、状态、所需证据和快照版本，不以 JSON 格式正确代替事实正确。时间关系错误、缺少引用、过早宣称结算或夹带操作字段时，整份模型方案回退。当前状态、金额规则、必需警示和只读检查仍由规则层决定。快照变化时会丢弃整段旧模型分析，不额外重试。

`GET /api/trader/trades/{id}/explanation?mode=rules_plus` 直接提供强化规则分析，不需要模型或 API key。原 `rules` 路径保留，`ai` 仍为显式实验入口。Streamlit 默认使用 Cross-event rules，AI 必须手动选择。三种方式都不能修改额度、批准、对账、提交、重试或执行交易。

| --- | --- | --- |

| 生成方案通过 / 回退 | 4 / 6 | 2 / 8 |

| 生成延迟 P50 / P95 | 5.357 / 6.756 秒 | 3.526 / 4.207 秒 |
| 有效评审 | 10/20 | 20/20 |
| 生成费用估算 | $0.0205688 | $0.0123564 |
| 模型评审费用估算 | $0.0307376 | $0.0303496 |
| 每轮总费用估算 | $0.0513064 | $0.0427060 |

本次合计 **60 个真实请求、USD 0.0940124**，含两轮生成和评审，不含此前排序版的六请求实验。没有自动重试或隐藏预热，缺失/非法输出没有删除，也没有在第二轮之后继续发起付费请求。两轮用量均完整返回，无未知计费请求。

费用按返回 tokens 和 [OpenAI 官方标准单价](https://developers.openai.com/api/docs/pricing) 估算：输入 $0.40、缓存输入 $0.10、输出 $1.60 / 百万 tokens；第二轮于 2026-10-21 核对。估算不替代最终账单。每次请求整体等待上限八秒、输出上限 1,400 tokens。延迟为应用内解释流程与网络，不代表生产 HTTP 吞吐量。

第二轮只调整输入表示和评审协议，案例、参考目标、生成模型、关系校验条件均保持。短别名解决了长编号输入问题，并降低耗时/费用，但没有改善模型的关系判断。评审用固定 AB/AC/BC 字段修复配对格式问题；第一轮仍保留原始协议下的无效评审，不将其静默改成有效结果。

## 第二轮解释质量

两次评审交换展示顺序，只有两次都同意的偏好才计为稳定胜/平/负。A/B/C 来源映射不传给评审模型。

| 比较 | AI 稳定胜 | 平 | 稳定负 | 顺序敏感或分歧 |
| --- | --- | --- | --- | --- |
| AI 对原规则版 | 1 | 6 | 0 | 3 |
| AI 对强化规则版 | 0 | 2 | 7 | 1 |

| 模型评审指标 | 原规则版 | 强化规则版 | AI 最终输出（含回退） |
| --- | --- | --- | --- |
| 参考目标覆盖 | 52/60（86.7%） | 60/60（100%） | 54/60（90.0%） |
| 清晰度均分 / 5 | 4.3 | 4.9 | 4.4 |
| 不确定性表述均分 / 5 | 4.5 | 5.0 | 4.5 |
| 未支持陈述 / 引用错误 / 危险操作建议标记 | 0 / 0 / 0 | 0 / 0 / 0 | 0 / 0 / 0 |

生成与评审使用同一个固定模型，可能存在自我偏好和相关错误；这些分数不是人工准确率。60 个目标机会来自十个案例的两个展示顺序，不是六十个独立样本。原规则版与 AI 最终输出的分数接近，也有对实质相同内容给出不同偏好的评审，说明评审本身有噪声。未做人工盲评，人工质量分保持为空。

“最终输出没有被评审标出错误”不能理解为原始模型没有编造：第二轮八份错误方案已被程序过滤，因此评审看到的是规则回退。第二轮只生成一条被接受的跨事件归因，另有一份合法但归因列表为空的方案。预先声明的显式关系覆盖为 AI **1/17**、强化规则 **17/17**；这是证据关系对象的覆盖，不是自然语言语义准确率。

原始输出中可直接观察到的问题包括：把晚到回执说成早于 UNKNOWN、把一个 UNKNOWN 说成重复 UNKNOWN、把回执误作终态结算，以及把倒序时间的事件操作数反置。这些关系未通过校验，没有获得业务操作能力。

## 如何使用与复查

交付的 HTML demo 是保留结果的静态回放，支持选择案例、并列比较三版解释、点击证据查看来源。它不连接数据库或模型，也没有交易操作按钮。

付费复现命令为 `python3 scripts/run-cross-event-eval.py --limit 10`；每次最多十次生成和二十次评审，使用私有 `.env.local`，产生独立结果目录。普通 CI 不会运行付费评测。现有原始结果可用 `scripts/build-cross-event-demo.py` 离线回放。

API key 仅保存在本地忽略文件中，不包含在报告、原始结果、源代码提交或交付包内。交易与额度状态由原有确定性执行路径管理；解释路径只有读取能力。当前应使用强化规则提供稳定跨事件解释，保留 AI 实验和评测工具；本次不支持“AI 已优于强化规则”这一结论。
